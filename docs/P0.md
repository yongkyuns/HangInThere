# P0: executable video-to-pose foundation

This change implements the first slice of [the POC](POC.md), not the final workout
app. No rep-count, chin-over-bar, dip-depth or accuracy claim is made.

## Implementation

One committed Xcode project, one SwiftUI app target and one hosted XCTest target.
Six app source files; no external runtime dependencies, app services, plugin
registries, generated project dependency or server. Swift 6 concurrency checking
is enabled; application code uses no `@unchecked Sendable` escape hatches or
`@preconcurrency` suppression. Metadata loading builds a fresh decoder graph in a
nonisolated async factory and transfers ownership into the actor with `sending`.

`VideoReplay` is one actor owning the reader, Core Image context and Vision
request. It returns one immutable analyzed frame per call. `ReplayModel` owns UI
state on the main actor and a single playback loop; session generations prevent
an old import from publishing into a newer session. Closing/replacing a session
releases security-scoped file access and the reader. Pause may finish one already
in-flight frame. Seeking and arbitrary speed controls are deliberately omitted.

The reader converts the track's orthogonal preferred transform to EXIF orientation,
renders an upright image capped at 1280 pixels on its long edge, then sends that
same image to Vision and SwiftUI. Landmarks become top-left-origin image pixels;
a tested aspect-fit map handles letterboxing. Non-orthogonal transforms fail
explicitly. P0 refuses ambiguous multiple-person results rather than switching
identities silently. No cross-frame identity qualification is claimed.

  Missing-file handling and stale-import rejection passed, but two actual Vision

  [Run 36260867067](https://github.com/yongkyuns/HangInThere/actions/runs/36260867067)

- Eleven hosted tests are now defined, including actual-frame UI-model playback.

  Preparation rejects missing pins, changed bytes, and changed length.
- The next runtime experiment uses an installed Xcode 26.3 / iOS 26.2 pair. No
  Apple model weights are copied, patched or redistributed; real-model failures
  still fail the simulator test step.
- A small native Mac check compiles the EXACT app `Pose.swift`, `VideoReplay.swift`
  and `VisionPoseEstimator.swift` with a test entry point. It checks 16 independent
  source timestamps, actual torso landmarks and restart. This adds no app runtime
  dependency or alternative implementation. Its result is recorded separately
  from simulator/device results; it is not a replacement qualification gate.

Latest runtime outcomes are recorded on [PR #1](https://github.com/yongkyuns/HangInThere/pull/1).
Do not mark P0 qualified while the actual app integration tests remain blocked.

## Remaining limits

The six-second CC BY 3.0 pull-up demonstration is a smoke fixture only: not
independently labelled joint ground truth, not a dip dataset, not a model comparison.
Simulator UI interactions, eight actual encoded orientation variants, camera
capture and physical-device latency/thermal behavior are not yet qualified.

The first iOS build caught a non-Sendable AVAssetTrack result crossing into the
actor. The ownership-transfer fix preserves full checking. The missing model
asset is a subsequent runtime failure, not the same compiler issue.
