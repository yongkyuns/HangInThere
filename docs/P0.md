# P0: executable video-to-pose foundation

This change implements the first slice of [the POC](POC.md), not the final workout
app. No rep-count, chin-over-bar, dip-depth or accuracy claim is made.

## Implementation

One committed Xcode project, one SwiftUI app target and one hosted XCTest target.
Six app source files; no external runtime dependencies, app services, plugin
registries, generated project dependency or server. Swift 6 concurrency checking
is enabled; application code uses no `@unchecked Sendable` escape hatches.

`VideoReplay` is one actor owning the reader, Core Image context and Vision
request. It returns one immutable analyzed frame per call. `ReplayModel` owns UI
state on the main actor and a single playback loop; session generations prevent
an old import from publishing into a newer session. Closing/replacing a session
releases security-scoped file access and the reader. Pause may finish one already
in-flight frame. Seeking and arbitrary speed controls are deliberately omitted.

The reader converts the track's orthogonal preferred transform to EXIF orientation,
renders an upright image capped at 1280 pixels on its long edge, then sends that
same image to Vision and SwiftUI. Landmarks become top-left-origin image pixels;
a tested aspect-fit map handles letterboxing. Non-orthogonal transforms fail
explicitly. P0 refuses ambiguous multiple-person results rather than switching
identities silently. No cross-frame identity qualification is claimed.

## Evidence and limits

- Local Linux Swift parser checks: executable source syntax only; not an iOS build.
- XCTest definitions: geometry, time, orientation mapping, true Vision/video smoke,
  restart, invalid file and stale-result behavior.
- GitHub workflow: pinned Xcode/runtime, real fixture acquisition, simulator tests,
  unsigned Release device compilation, retained logs/results.
- Real fixture: one six-second CC BY 3.0 pull-up demonstration. Not independently
  labelled pose ground truth, not a dip dataset, not a model comparison.
- Simulator UI interactions, eight actual encoded orientation variants, camera
  capture and physical-device latency/thermal behavior are not yet qualified.

CI run outcome and fixture digest must be verified on the PR before P0 is marked
qualified. A green smoke test does not change the exercise-accuracy status.
