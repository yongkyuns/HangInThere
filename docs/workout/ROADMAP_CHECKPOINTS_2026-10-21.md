# Outcome

Make the app a dependable workout log and a useful progression coach, including for users whose practice consists of hangs, support holds and partial attempts. Every coaching conclusion must identify its measured evidence and uncertainty. Preserve shared analysis/application policy across iOS and Android, with native capture/inference/rendering adapters.

## Current foundation and qualification limits

Automatic sets, source-time phases, bilateral angle metrics, zero-rep practice, durable journals, adjustable goals and milestones are implemented in #30, stacked on #29. These are engineering capabilities; original-capture accuracy, Apple simulator model/decoder behavior and physical Android performance remain unqualified. Existing labels, accuracy checks, color assertions and performance budgets must remain intact. The two authorized phone recordings are development regressions, not a held-out benchmark. Do not upload user video/pose data automatically.

## Priority 1 — reliable measurements and transparent uncertainty

- [x] Restore legacy evaluation harnesses after shared-framework integration; distinguish infrastructure failures from exercised tracking failures. Implemented in #30; source `52f43dc` passes native Mac, shared analysis, dataset/temporal/controlled evaluation and Android API29/API35.
- [x] Add shared, versioned attempt assessments distinguishing completed cycles, observed partial movements, unrecorded returns and interrupted observations. Expose evidence/reasons in both native reviews; avoid calling tracking failure athlete failure.
- [x] Report observed time/arm coverage and unavailable measurements without manufacturing confidence scores or inferring anatomical validity from landmark scores.
- [x] Stabilize phase boundaries against pose jitter with bounded filtering/hysteresis, without crediting missing intervals or changing count eligibility.
- [ ] Build an independently annotated session benchmark: athletes, devices, equipment, camera placement, lighting, occlusion, assisted movements, negatives, holds and incomplete attempts. Freeze labels/splits before tuning; hold out athletes/source sessions.
- [ ] Evaluate rep precision/recall and exact-set counts, false automatic starts/ends, phase-boundary and hold-duration error, coverage, and repeatability. Define supported recording conditions and explicit release gates from that evidence.
- [ ] Qualify end-to-end camera/sensor timing, dropped frames, latency, battery and thermal behavior in sustained physical-device sessions on both platforms. Emulator/host performance stays separately labelled.

Acceptance: uncertainty reasons agree across iOS/Android; accepted-without-return never becomes a completed rep; gaps never earn hold time; historical summaries/recovery preserve evidence; every regression stays in CI; failed/unsupported qualification remains visible.

## Priority 2 — review, correction and comparable progress

- [x] Let users correct exercise/rep classification and split/merge sets using a versioned correction ledger; retain immutable original measurements and regenerate derived summaries/goals.
- [x] Provide optional local review media with explicit retention/delete controls, without automatic upload or training consent.
- [x] Track comparable-session progress in hang/support duration, partial excursion, return timing and consistency. Preserve assisted/negative/ordinary exercise context and camera setup so unlike measurements are not silently compared.
- [x] Make practice and completed-rep evidence distinct throughout charts, history, achievements and export.

Acceptance: corrections survive restart and deterministically update derived analytics; uncertain observations cannot silently create milestones; repeated comparable measurements can demonstrate beginner progress before the first completed rep.

## Priority 3 — personalized coaching and progression

- [x] Add user-selected goals, assistance/load, perceived effort and optional readiness/recovery context.
- [x] Base suggested goals on several recent reliable comparable sessions, not solely a best-ever result; keep chosen goals fixed until explicitly changed.
- [x] Produce one actionable next focus with a plain-language explanation, source measurements and confidence limitations.
- [x] Add descriptive consistency/plateau detection and planned-versus-completed sessions with explicit same-day/context/coverage evidence and a user-selected workout link.
- [ ] Have training rules and progression suggestions reviewed by a qualified coach.

Acceptance: feedback remains useful for hang-only users; missing footage never becomes an asserted weakness; advice can be traced to evidence; recommendations do not claim force, fatigue, calorie expenditure, chin clearance or dip depth that the pipeline has not validated.

## Priority 4 — sessions, habit and equipment-friendly UX

- [x] Group sets into workouts with exercise transitions, rest periods, planned work and interruption recovery.
- [x] Provide large, accessible start/end/tracking-loss/resume cues and low-distraction after-set feedback in both native apps.
- [ ] Test those cues from actual equipment distance and in gym noise in observed usability trials.
- [x] Provide a concise after-set result, chosen-goal progress and one useful observation; improve chart accessibility and correction discoverability.
- [x] Track weekly consistency and milestone history, avoiding incentives that mistake measurement quantity for training quality.

Acceptance: beginners can independently position the phone, recognize tracking start/stop, review/correct a session and understand the next focus in observed usability trials.

## Priority 5 — maintainable production foundation

- [x] Define reusable exercise profiles and conformance fixtures; continue consolidating common application/counting policy where viable while retaining native vision adapters.
- [x] Separate measured events, quality assessments, user corrections and coaching decisions; version each contract and test migrations/recomputation.
- [x] Introduce indexed/paginated durable history as volume grows; add export, backup/restore and deletion.
- [x] Add consent-aware, content-free diagnostic reporting and a versioned device/model performance-matrix interface with predeclared evaluation gates. Sustained physical-device measurements remain required by Priority 1.

Acceptance: new exercises reuse shared lifecycle/analysis interfaces; storage is bounded and recoverable; history remains responsive at realistic scale; diagnostic collection respects local media boundaries.

## Implementation sequence

1. Repair evaluation integration and introduce shared attempt-evidence assessments in both native reviews.
2. Extend annotated evaluation, stabilize phases and qualify confidence/measurement validity.
3. Add corrections and comparable-session analytics.
4. Build evidence-based coaching, then session/habit features.

This issue is the roadmap; each implementation PR should reference it, state what was actually validated and leave the remaining checklist open.
